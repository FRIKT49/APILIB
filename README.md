# 🚀 API Library — Каталог сторонних API для разработчиков

**API Library** — современное, быстрое и полнофункциональное веб-приложение в формате онлайн-библиотеки и каталога сторонних API. Разработано на чистом технологическом стеке (**HTML5, CSS3, Vanilla JavaScript ES6+ Modules**) и облачной платформе **Firebase (Authentication, Cloud Firestore, Security Rules)**.

## ✨ Особенности и возможности

- **Каталог API**: Отображение карточек с логотипом, категорией, тегами, типом авторизации, форматом данных (JSON/GraphQL/XML), признаком Free Tier и рейтингом.
- **Поиск в реальном времени**: Оптимизированный префиксный поиск и поиск по ключевым токенам (`searchKeywords`) с защитой от избыточных чтений через debounce.
- **Фильтрация и сортировка**: Фильтры по категориям (AI, Weather, Maps, Finance и др.), типам авторизации, стоимости (Free, Freemium, Paid), формату и сортировка по рейтингу, популярности, дате и названию.
- **Real-Time синхронизация**: Использование Firestore `onSnapshot()` — любые изменения каталога или рейтингов мгновенно отображаются у пользователей без перезагрузки.
- **Пагинация**: Курсорная пагинация Firestore через `limit()` и `startAfter()`.
- **Детальная страница API**: Полное описание, интерактивный список ключевых возможностей, таблица технических спецификаций, внешние ссылки на документацию и официальный сайт.
- **Система отзывов и оценок**: Оценка от 1 до 5 звезд, возможность для пользователя писать, редактировать и удалять свой отзыв. Автоматический денормализованный пересчет рейтинга API.
- **Избранное (Favorites)**: Сохранение API в персональную подколлекцию `users/{userId}/favorites/{apiId}`.
- **Личный кабинет**: Просмотр и редактирование профиля, вкладка избранных API и история собственных отзывов.
- **Админ-панель**: 
  - Защищена клиентским роутером и серверными `firestore.rules`.
  - Метрики и статистика (всего API, пользователей, отзывов, категорий, топ по просмотрам).
  - Полный CRUD (создание, чтение, редактирование, удаление с модальным подтверждением).
  - Управление пользователями и назначение роли `admin`.
  - Модерация всех отзывов.
  - Кнопка импорта 18+ реальных API в один клик.

## 🛠 Технологический стек

- **HTML5**: Семантическая доступная верстка.
- **CSS3**: CSS Custom Properties (переменные для тем оформления), Flexbox, CSS Grid, адаптивность для экранов от 320px до 4K. Никаких сторонних тяжелых CSS-фреймворков (Tailwind/Bootstrap).
- **Vanilla JavaScript (ES6+)**: Нативные ES6 Modules (`import`/`export`), `async/await`, компонентная архитектура без React/Vue/Angular.
- **Firebase v10/v11 Modular SDK**: Официальный CDN-импорт браузерных ES-модулей без сборщиков (Webpack/Vite не требуются для запуска).
- **Firebase Authentication**: Email/Password авторизация, сессии, сброс паролей.
- **Cloud Firestore**: Документоориентированная NoSQL база данных в реальном времени.
- **Firebase Security Rules**: Строгое разграничение прав доступа.

## 🚀 Быстрый старт и локальный запуск

Так как проект использует нативные ES6 Modules, запускать его необходимо через любой локальный HTTP-сервер (прямое открытие через `file:///` блокируется браузерами по соображениям безопасности CORS для модулей).

### Вариант 1: VS Code Live Server
1. Откройте папку проекта в VS Code.
2. Установите расширение **Live Server**.
3. Нажмите правой кнопкой на `index.html` → **Open with Live Server**.

### Вариант 2: Python (встроенный сервер)
В терминале внутри папки проекта выполните:
```bash
python -m http.server 8080
```
Затем откройте в браузере: `http://localhost:8080`

### Вариант 3: Node.js (npx serve)
```bash
npx serve .
```

## ⚙️ Пошаговая настройка Firebase

### 1. Создание проекта
1. Перейдите в [Firebase Console](https://console.firebase.google.com/).
2. Нажмите **Add project** (Добавить проект), введите название, например `api-library`, и нажмите **Continue**.
3. В обзоре проекта нажмите на иконку **Web (`</>`)**, чтобы зарегистрировать веб-приложение.
4. Введите имя приложения (например, `api-library-web`) и нажмите **Register app**.
5. Скопируйте объект `firebaseConfig` и вставьте его в файл `js/firebase.js`:

```javascript
export const firebaseConfig = {
  apiKey: "ВАШ_API_KEY",
  authDomain: "ВАШ_PROJECT_ID.firebaseapp.com",
  projectId: "ВАШ_PROJECT_ID",
  storageBucket: "ВАШ_PROJECT_ID.appspot.com",
  messagingSenderId: "ВАШ_SENDER_ID",
  appId: "ВАШ_APP_ID"
};
```

### 2. Активация аутентификации
1. В левом меню консоли выберите **Build → Authentication**.
2. Нажмите **Get started**.
3. Во вкладке **Sign-in method** выберите **Email/Password**.
4. Включите первый тумблер (**Email/Password**) и нажмите **Save**.

### 3. Создание базы данных Firestore
1. В левом меню выберите **Build → Firestore Database**.
2. Нажмите **Create database**.
3. Выберите регион (например, `europe-west1` или ближайший к вам).
4. Выберите режим запуска (можно выбрать **Start in production mode** или **Start in test mode**).

### 4. Настройка правил безопасности (Security Rules)
1. В Firestore перейдите во вкладку **Rules**.
2. Скопируйте содержимое файла `firestore.rules` из нашего репозитория и вставьте в редактор правил в консоли.
3. Нажмите **Publish**.

### 5. Создание составных индексов (Indexes)
Для выполнения сложных запросов с одновременной фильтрацией (`where`) и сортировкой (`orderBy`) Firestore требует составные индексы.
1. В Firestore перейдите во вкладку **Indexes → Composite**.
2. Вы можете добавить индексы вручную или развернуть файл `firestore.indexes.json` через Firebase CLI:
```bash
firebase deploy --only firestore:indexes
```
Либо кликайте по ссылкам генерации индексов, которые Firebase автоматически выводит в консоль браузера (`F12`), если запрос встречает недостающий индекс.

## 👑 Создание первого администратора

Безопасность проекта основана на роли `role: "admin"` в документе пользователя `users/{userId}`:

1. Запустите сайт локально и перейдите на страницу `register.html`.
2. Зарегистрируйте аккаунт со своим email (например `admin@example.com`). По умолчанию ему будет присвоена роль `role: "user"`.
3. Откройте **Firebase Console → Firestore Database → коллекция users**.
4. Найдите документ с вашим пользователем.
5. Измените поле `role` со значения `"user"` на `"admin"`.
6. Обновите страницу сайта — в навигационной панели появится пункт **Админ-панель**, а доступ к `admin.html` будет разблокирован!

## 🧠 Архитектура Firestore и оптимизация

### Поиск без скачивания всей коллекции
Полнотекстовый поиск SQL-типа `LIKE '%термин%'` отсутствует в Firestore. Скачивание всей коллекции в браузер категорически не рекомендуется из-за расхода трафика и стоимости квот Firestore.
**Наше решение**:
1. При создании/редактировании каждого API генерируется массив `searchKeywords` из нормализованных слов названия, описания, категории и тегов.
2. Также сохраняется поле `nameLower`.
3. Поиск выполняется через комбинированные запросы:
   - Префиксный поиск по названию: `where("nameLower", ">=", q).where("nameLower", "<=", q + '\uf8ff')`.
   - Токенизированный поиск: `where("searchKeywords", "array-contains", q)`.
4. Ввод пользователя дебаунсится (задержка 350мс), чтобы не отправлять запросы на каждый введенный символ.

### Денормализация рейтинга
Вместо того чтобы при каждом открытии каталога загружать все отзывы и вычислять средний рейтинг на лету, поля `rating` и `ratingCount` хранятся непосредственно в документе `apis/{apiId}`. При добавлении или удалении отзыва происходит быстрый пересчет и сохранение нового значения.

### Курсорная пагинация
Пагинация каталога реализована через курсоры `startAfter(lastVisibleDoc)` с ограничением страницы `limit(12)`. Это позволяет экономить операции чтения и обеспечивает максимальную скорость отклика.

### Real-time обновления через onSnapshot
Каталог и отзывы подписаны на `onSnapshot()`. Если администратор изменит статус API или пользователь оставит отзыв, изменения отобразятся на экранах всех открытых вкладок без перезагрузки.
